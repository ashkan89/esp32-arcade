# Gameplay audit

Completed source review: 2026-10-11. Stable catalog IDs 0–51 are preserved. Each row refers to that game’s own source, not just a shared engine. Review covered input/update/render, collision, scoring/stages, generation/RNG, pools, pause/restart, and sound events. The chosen changes prioritize actual defects. Retained mechanics are deliberate dispositions, not unfinished generic-AI work.

All 52 games use a catalog-specific original track and independent cosmetic RNG. `tests/improvements.cpp` compares score, lives, stage, ending and gameplay RNG every tick across effects settings and both Atari modes. Individual `verify<Game>()` routines cover campaign lifecycle/rules for games 8–51; `tests/rules.cpp::RuleTests` covers the first eight, shared shooter rules and final bosses. This is automated invariant coverage, not a claim of human play quality.

## Shared integration and resource findings

`Game.h::baseStart` normalizes zero seeds and derives an independent cosmetic stream. `ShooterBase.cpp::explode` and `Campaign.h::burst` no longer advance gameplay RNG. The console maintains a seeded run stream and reports the effective seed. The fixed 60 Hz clock retains bounded four-step catch-up and transition reset; input edges are consumed once.

`AudioSequencer.cpp` owns flash-resident composition and bounded event arbitration; `Hardware.cpp::Audio` alone writes LEDC channel 0. Rendering services audio between internal SPI strips. Score storage v3 has separate difficulty/rules records and preserves historical mixed records. Decoding reads bytes directly into one temporary Settings object rather than nesting multiple 2 KiB migration buffers on the ESP32 loop stack.

`Registry.cpp::gameFor` retains the shared 8,192-byte internal arena, with compile-time per-game size checks in `Registration.h`. Gameplay and audio use fixed arrays/pools, with no per-frame heap allocation. Bounded BFS uses at most 323 cells; only appropriate maze games use it. WROOM retains RGB332 plus internal transfer staging, while WROVER retains PSRAM RGB565 buffers and optional banked history. Rules do not depend on PSRAM or flash capacity.

## Remaining validation limits

Enhanced River validation proves a conservative left-route interval through depots and the bridge at maximum speed, with conservative slow-speed fuel spacing. Objects are kept off that route except collectible depots and the shootable bridge. It does not prove every possible pilot action succeeds; shooting depots intentionally removes fuel opportunities. Classic generation remains unchanged and is not newly advertised as mathematically fair.

Enhanced Keystone uses the officer’s actual 60-tick upward escalators and the shared timed lift on floors 0–2. Descent requires boarding the lift; both characters in the same cabin can result in capture. Sprite and minimap positions interpolate during travel. The roof has no lift/descent shortcut. Classic’s historical thief route is preserved. Human balance of later-tier hazard combinations, catch windows and composition quality requires physical play/listening tests. See BUILD_AND_TEST.md.
